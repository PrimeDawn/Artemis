# Version 运行账本：v0.1

## 当前状态快照（2026-11-02，优先于下方历史流水）

**方向变更**：产品形态从「手机 → WebRTC → OBS 浏览器源」改为「手机 = Windows 11 系统摄像头与麦克风」。
旧接收页、接收票据与 OBS 浏览器源路线作废；配对、信任、发现、信令与前台生命周期行为继续保留。

已交付并合入 dev：SDK 与工具链、离线配对与信令（PR #3）、应用层无感改造（PR #4）、系统摄像头设备层（PR #5）、手机画面链路（PR #6）。
已交付并须保持不退化：配对/信任/信令（当前 Node 52 项、JVM 18 项通过），APK 可构建；OBS 可枚举 `Artemis Camera` 并显示真机 720p30 画面（约 30fps）。
仍缺：音频链路（依赖用户自备第三方虚拟声卡）与真机验证基线。按 D-012，本版不自研虚拟麦克风驱动、不涉及签名：装有受支持虚拟声卡时才有声音，未装则只传视频。
已知边界：仅 720p30；端到端延迟未实测；真实手机换 IP 未测；实际断公网按 D-006 未测；Windows 端仍是脚本启动，未打包。

传输选型已定 **H.264 over TCP**（参照 scrcpy 的包格式与 MediaCodec 编码路径），设备层经共享内存解耦。

Spec 序列：应用层无感改造 → 设备层 → 手机画面进 OBS → 音频 → 真机验证；前 3 项已完成。
原 `SPEC-media-obs` 作废，由 `SPEC-phone-media`（视频）与 `SPEC-audio-device`（音频）替代。

### 历史快照（2026-10-31）

Spec2的自动发现、电脑单击选手机、首次允许后持久信任、无固定连接期限、自动恢复及授权信令已实现。真实S24已完成首次连接与控制流程，前台常亮、切App暂停/返回恢复及省电锁屏→正常解锁连续恢复均有通过记录。最新连续流程全程同一服务，锁屏2649ms清除旧会话、解锁建立新会话。当前已原位归档，PR #3（https://github.com/PrimeDawn/Artemis/pull/3）待审阅、未合并；手机真实换IP仍未测，实际断公网按用户要求不测，音视频采集、媒体WebRTC及OBS播放尚未实现。 测试按D032取消五分钟硬上限；证据按D035精简。下方带旧日期的状态不代表当前阻断（该段方向已于 2026-11-01 被系统设备路线取代）。

## 1. 版本目标

验证 Artemis 的核心技术路线：把 Galaxy S24 / Android 16 变成 Windows 11 的系统摄像头与系统麦克风——
手机摄像头画面经 DirectShow 虚拟设备出现在 OBS 及其他应用，手机麦克风经虚拟音频设备成为系统输入，
并形成可复现的实验原型和选型证据。

本版本对应产品规划 M0 技术预研。原「手机 → WebRTC → OBS 浏览器源」形态已作废，改为系统设备形态：
手机不再需要 OBS 浏览器页，OBS 只作为验收代表（能选到 `Artemis Camera` / `Artemis Microphone` 并录出音画）。
为验证所需建立的最小安卓端、Windows 原生接收客户端与虚拟设备属于研究原型；
完整产品基础工程、成熟交互和面向普通用户的分发仍属于后续版本。

当前已交付工具链、配对/信令、应用层改造、系统摄像头设备层与手机画面链路；音频采集、媒体音频与虚拟音频设备尚未实现，真机验证基线未启动。

来源：[产品规划](../../../产品规划.md) 的第 3、4、7、8 节；[版本规划报告](plan.html)；[方向调整决策](#7-决策记录) D-007 至 D-011。

## 3. 各 Spec 的规划验收边界

### SPEC-sdk-toolchain
- 记录 Android SDK、JDK、Gradle/AGP、Kotlin、Node.js 与 WebRTC SDK 的实际版本及来源。
- 核验 WebRTC 依赖的许可证、原生 ABI、页面大小要求，以及 minSdk 29 / Android 16 目标环境适配风险。
- 从文档步骤可重复构建最小 APK、启动 PC 实验服务；不绑定未经验证的第三方 AAR。
- 输出选型与最小可构建证据；设备访问缺失时明确标记待真机验证。

### SPEC-offline-pairing
- 保留无需公网的配对和信令能力，无公共 STUN/TURN、云端信令或在线 CDN 依赖；本轮在保持公网连接的局域网中验证功能，并检查配置、代码和应用请求记录中的公网依赖。
- 本轮不执行实际断公网流程，不改主机、路由器、代理或防火墙来制造断网环境；实际断公网运行标记“未实测”，不阻断当前 Spec 与 v0.1 推进。补测须由用户另行授权。
- 证明知道 IP 地址本身不能取得媒体接收权限；验证首次确认、短期身份挑战/票据时效、撤销与未授权拒绝，长期信任及活动连接不设固定期限。
- 对本地 TLS 证书信任、二维码绑定或明确的替代信任方案做可行性验证并记录取舍。
- 不把 WebRTC 媒体加密当作信令安全已解决；若可用方案与产品约束冲突，交回用户决策。

### SPEC-app-refactor
- 从「OBS 浏览器源」形态改为新方向下仍成立的形态，用户层面无感：已交付的配对、信任、发现、连接与恢复行为不变。
- 删除旧接收页（`receiver/public/receiver.html`、`receiver.js`）与接收票据机制（`issueReceiverTicket` / `redeemReceiverTicket` / `attachReceiver` / `lostReceiver`），清理 `/ws/receiver` 升级路径与相关路由。
- 保留配对/信任/信令全部行为；R-04 的语义由「控制页发单次接收票据」改为「单活动接收客户端」，不再以浏览器页为载体。
- 产品文档（`产品规划.md`、`GOALS.md`、`work-ledger.yaml`、`README.md`）从「OBS 浏览器源」改为「系统摄像头/麦克风」。
- 不新增任何媒体或设备功能；本 Spec 是纯重构，必须可回归验证。

### SPEC-device-layer
- 以 `webcamoid/akvirtualcamera` 的结构为参考，实现 64 位 DirectShow 源过滤器，通过共享内存 IPC 从外部进程取帧。
- 先输出合成画面（色条 + 时间戳/帧号），不接手机。
- 验收：OBS「视频采集设备」中出现 `Artemis Camera`，预览有画面，录制 30 秒回看有画面。
- 不要求其他应用通过；音频不在本 Spec 内。

### SPEC-phone-media
- 手机端 Camera2 采集 + MediaCodec 编码 H.264；经已配对鉴权的 TCP 连接传到 Windows 原生客户端。
- 包格式参考 scrcpy `Streamer.java`：12 字节头（PTS + 标志位 + 包长度）+ 编码数据。
- Windows 客户端用 FFmpeg 解码，写入共享内存供 `SPEC-device-layer` 的过滤器读取。
- 以 720p / 30 fps 为实验基线，记录实际编码、分辨率与帧率。
- 验收：OBS 选中 `Artemis Camera` 能看到手机实时画面，录制 30 秒回看有画面。
- 媒体不走 Node.js 转码；配对/信任/信令通道复用现有实现。

### SPEC-audio-device
- 目标改为「把手机麦克风的声音送到用户机器」，不要求出现系统级麦克风设备；本 Spec 不写内核驱动、不涉及签名。
- 前提：用户自备第三方虚拟声卡（如 VB-CABLE、VoiceMeeter）。软件探测成对的渲染/采集端点，命中则把音频输出到其渲染端，用户在 OBS/Zoom 里选对应采集端。
- 未安装虚拟声卡的机器：视频照常，音频不可用，界面明确提示原因与安装指引；不静默、不崩溃、不影响视频。
- 跳板被卸载或设备消失时关闭音频并显示原因，不退出进程。
- 其他软件是否支持不在本项目范围内；不承诺除 OBS 类以外的兼容性。
- 与视频不绑在一起验收。

### SPEC-validation-baseline
- 固定并记录手机系统、Windows、OBS、网络环境和构建版本，附验证命令、日志或录像索引。
- 保持公网连接，在局域网内从首次配对到 OBS 看到 `Artemis Camera` 执行一次完整复测；保留离线功能目标，实际断公网验证按 D-006 暂不执行。
- 以 OBS 能否枚举 `Artemis Camera` 并录出画面为必达标准；音频部分只在目标机器装有受支持的虚拟声卡时验证「选中其采集端能听到手机麦克风声音」，未装则如实记「音频不可用、原因已提示」，不记为失败。
- 通过可复现方法测量延迟和音画偏差，对照产品目标 300 ms / 150 ms 报告实际结果。
- 输出原型 APK、Windows 客户端与虚拟声卡安装步骤、依赖许可证与研究结论；指标超标或设备缺失不得记为达标。

以上为 v0.1 技术预研证据门槛，不替代一期验收。

## 5. 版本验收与发布边界

1. 本版新增 5 个 Spec（应用层改造、设备层、手机画面、音频、真机验证）全部完工，分别保留已确认计划、实现记录与真实验证证据；待解决的问题明确登记。
2. 已交付的配对/信任/信令行为不得退化：当前 Node 52 项、JVM 18 项测试仍须通过，APK 仍可构建。
3. 核心验收：OBS 能枚举 `Artemis Camera` 并录出画面；装有受支持虚拟声卡时，音频输出到该跳板且其采集端能收到手机麦克风声音，未装则如实记「音频不可用」并说明原因。保留离线功能并检查无公网依赖。按 D-006，实际断公网运行不纳入本轮必测门禁，报告明确“未实测”。
4. 延迟、同步等数据如未达到产品目标，保留差距、处理方案并取得用户明确处置结论，不能宣称已达标。
5. 设备层或媒体链路的关键可行性验证失败时，暂停、记录失败证据并重订路线，不静默降级为浏览器源方案。
6. 达到本研究里程碑验收后，才由 version-release 进行集成验收和实验版发布；预期首个发布 Tag 为 v0.1.0，本次不打 Tag。
7. 1.0.0 稳定发布、完整交互、多设备兼容和全部一期稳定性验收不在本版本内。
