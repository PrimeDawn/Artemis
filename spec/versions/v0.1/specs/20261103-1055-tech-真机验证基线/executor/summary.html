2. 执行中修复的缺陷

编号现象根因处理
I-002手机端持续发帧，PC 端视频通道始终没连上-MediaPort 只传给了解码进程；接收服务读 config.mediaPort，而该字段从未从环境变量解析，固定连 3450解析 ARTEMIS_MEDIA_PORT + 脚本透传 + 两个单测
I-003openssl 候选全部探测失败脚本 $ErrorActionPreference='Stop'，openssl 往 stderr 写进度被 PowerShell 当成错误抛出改用 Start-Process 重定向后再判退出码
I-004脚本中文注释导致解析报错文件保存为无 BOM 的 UTF-8，Windows PowerShell 5.1 按 ANSI 解码以 UTF-8 BOM 保存
I-005OBS 新建源报 DecodeDeviceId failed，画面全黑video_device_id 只写了 Artemis Camera；OBS 需要 名称:@device#3Asw#3A{CLSID}\{PIN} 完整形式改用完整设备标识
I-006依赖清单缺 FFmpeg解码进程引入 FFmpeg 后清单未同步补入清单并说明 GPL 分发义务

4. 未做与偏差

项说明
权限授予方式相机与麦克风权限用 adb shell pm grant 授予，不是点系统弹窗：当前模型无法读图，Samsung 权限对话框的 uiautomator 树为空，盲点风险高。配对确认仍走真实点按。
OBS 交互方式通过 obs-websocket 建源、录制，不点 GUI；设备标识取自 OBS 场景文件里既有的正确值。
画面首次全黑首次录制时源用了错误设备标识、且手机所在环境无光；改用完整标识并在有光条件下重录后画面正常。
遗留风险强杀包装脚本时子进程（node / 解码进程）会逃逸并占用端口，本轮手动清理；脚本本身在正常退出时会回收。
