2. 真机复测与缺陷闭环

六项缺陷

首轮真机测试暴露六个缺陷（权限未申请、音频不重连、Opus 配置包缺失死循环、AOPUSHDR 被误判、重连截断 WAV、半开连接堵住 accept），逐项分析与修复见 debug-001 与 debug-001-fix。修复后复测即本节数据。

  • 音频产物：audio-tc08-final.wav，ffprobe 报 pcm_s16le / 48000 Hz / 1 ch / 61.987 s。
  • 重连序列：audio channel connected → closed → connected → decoder ready，说明断流后是重新建链而不是复用死连接。
  • 手机侧日志：config bytes 与 sent audio frames 持续增长，编码器为 c2.android.opus.encoder。
证据文件已清理

按用户要求，收尾时删除了 tester/artifacts/test-logs/ 下的全部日志与录音文件（约 17 MB）；本报告保留当时的命令、结果与结论，原始文件不再随仓库交付。

3. 环境与偏差

项情况处置

首轮把 TC-08/09 记未实测实际手机一直连着，adb 一次偶发为空导致误判改用真机执行；报告 r2 更正

4. 结论与风险

  • 音频链路在真机上成立：采集 → 编码 → 独立通道 → 解码 → 落盘，断流可自愈。
  • 仍未验证：CABLE 设备输出（v0.1.1）、OBS 对本轮改动的枚举复测、长时间运行。
  • 已知遗留：手机端调试日志较密（每 4800 帧一条），收尾前可降级，但不影响功能。
