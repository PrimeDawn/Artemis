计划结论

12 项用例分三层：通道与解码的单元/进程内层、真实进程的链路层、OBS 设备层。 默认使用真实 Opus/AAC 码流与真实进程，只有「Node 的 socket 边界」和「MediaCodec 需 Android 运行时」两处必须用替身/仪器化，并逐条写明原因。 regulator 与重连一律用可控时钟与短样本，不安排真实等待。

1. 测试策略

层级手段判定依据
单元层真实编译运行：C++ 帧头测试、Kotlin JVM 单测、Node 单测退出码 0 + 断言；日志落盘
链路层真实进程：真实 Opus/AAC 码流 → decode-host → 真实 WAV；ffprobe 读回校验样本数、时长、声道、采样率自洽，内容可辨别
设备层装有受支持虚拟声卡时，由其采集端在 OBS 收回手机声音混音器有电平，录制回看有声音
数据真实性

不使用伪造 PCM 充当「音频链路通过」的证据；解码用例喂真实 Opus/AAC 码流（由 FFmpeg 从真实录音编码得到）。 允许的两处非真实件：① Node 的 MediaSocket 用内存替身（既有测试基线如此，真实 TLS 链路另由链路层与历史 E2E 覆盖）；② MediaCodec 必须在 Android 运行时执行，无法在 JVM 单测中构造。

3. 执行约束

  • 不把真实时长当测试步骤：时间相关问题用可控时钟与样本数核对，regulator 与重连一律短样本。
  • 每轮聚焦受影响的用例，不因改一行就跑全部 12 项；全量只在提交前跑一次。
  • TC-10 依赖目标机器已装受支持虚拟声卡；不具备时记「未实测」并写明原因，不记为通过。
  • 证据一律由测试运行自动产出并写入 tester/artifacts/test-logs/<run-id>/，不手写、不回填。

4. 通过与升级规则

TC-08/09 失败阻断：核心链路不成立
