调试报告：真机音频链路的六项缺陷

类型 debug Spec spec/versions/v0.1/specs/20261102-1117-tech-虚拟麦克风音频链路 角色 spec-debugger 模式 gated 分支 tech/spec-20261102-1117-audio-device ← dev 创建 2026-11-02 修订 r1（2026-11-02）
结论

单元测试全绿但真机链路一帧音频都没到 PC：六个独立缺陷串在一起，分别是权限未申请、音频通道不重连、Opus 配置包缺失导致死循环、三星 Opus 头变体被误判为 AAC、重连后 WAV 被截断、半开连接堵住 accept。全部已修复并在真机上复测通过。

1. 现象

手机（SM-S9210 / Android 16）与 PC 配对成功、视频帧正常到达（frames=1191），但音频通道只有 audio channel connected，PC 端 WAV 始终 0 字节，日志里没有 audio decoder ready。

2. 逐项根因

编号现象根因证据
D1 AudioRecord 初始化失败 RECORD_AUDIO 只在 manifest 声明，运行时只申请了相机；权限拒绝时 AudioRecord 返回 -20 dumpsys package 显示 granted=false；logcat Error code -20 when initializing native AudioRecord
D2 Wi-Fi 断开后音频永不恢复 AudioStream 只把 onClosed 转成状态，没有像视频那样重连 断网 6 秒后 audio blocks 不再增长
D3 音频帧一条都发不出去 drainOutput 里 getByteBuffer("csd-0") ?: continue，Opus 编码器不提供 csd-0 时该分支死循环，永远走不到取输出帧 手机日志只有编码计数、没有 sent audio frames
D4 PC 报 audio decoder unavailable 三星的 Opus 配置包开头是 AOPUSHDR 而非 OpusHead，被误判成 AAC，用 AAC 解码器打开失败 decode-host 日志 audio config bytes=83 head=AOPUSHDR
D5 重连后 WAV 变小（1.87 MB → 1.18 MB） 每条连接重建 sink 并以 wb 打开同一文件，重连即截断；随后又改成「进程内单 sink」但结束时仍调用 close() 文件长度在重连瞬间下降；serveAudio 末尾残留 if (sink) sink->close();
D6 断网恢复后新连接进不来 音频 accept 循环串行处理，旧连接半开时阻塞在 recv，新连接只排在 backlog 手机持续 sent audio frames 增长，PC 端 blocks 不增长，直到超时

3. 为何单测没拦住

这六项全部落在「Android 运行时 / 真实设备 / 真实网络中断」这一层：JVM 单测覆盖的是编码器选择，C++ 单测覆盖解码与缓冲，冒烟用的是合法 AAC 与正常连接。D1–D6 只有在真机上才会出现，这正是先前把 TC-08/09 记「未实测」时留下的空洞。
