实现方案：手机麦克风 → PC 音频汇 → 系统音频输入设备

类型 plan Spec spec/versions/v0.1/specs/20261102-1117-tech-虚拟麦克风音频链路 角色 spec-writer 模式 gated 分支 tech/spec-20261102-1117-audio-device ← dev PR — 创建 2026-11-02 修订 r5（2026-11-02）
方案结论

照 scrcpy 的音频实现办：新增独立 /audio 通道，复用现有 12 字节包头，视频路径一行不改；手机端 AudioRecord + MediaCodec Opus（AAC 回退）；PC 端 FFmpeg 解码后经 regulator 自适应缓冲交给 sink。 sink 三实现：WAV 落盘（可判定证据）、默认设备播放、写入用户自备虚拟声卡的渲染端。系统麦克风由用户已装好的第三方虚拟声卡提供，本 Spec 不自研驱动、不涉及签名。

1. 目标与范围

项内容
目标手机麦克风采集并编码，经已配对鉴权的独立音频通道送到 PC，解码后写入虚拟音频输入设备，OBS「音频输入采集」能选到该设备并录出人声。
范围内手机端音频采集/编码/权限/生命周期；/audio 通道与绑定校验；PC 端 Opus/AAC 解码、regulator、sink 抽象；虚拟声卡端点探测与输出路由（含未命中时的降级与提示）；上述改动的单元测试。
范围外内核驱动与代码签名、其他软件兼容性、静音开关、回声消除、降噪、多声道、1080p 音画同步调优、长时段稳定性、其他机型适配。
不退化约束视频链路（Camera2 → H.264 → /media → 共享内存 → Artemis Camera）行为不变；FrameHeader.h 与 MediaWire.kt 语义不变；Node 52 项与 JVM 18 项既有测试继续通过；APK 仍可构建。

3. 通道与帧格式

项做法理由
连接 新增 wss://<pc>:<port>/audio，与 /media 平级；同样先发 JSON 绑定（pcId / deviceId / sessionId），通过后才接收二进制 与 scrcpy 的三 socket 结构一致；音频帧小且延迟敏感，不能被大视频帧阻塞
帧头 不改：沿用 8 字节 pts+flags + 4 字节长度；bit63 会话首包、bit62 配置包、bit61 关键帧（音频不使用） 音频流里每一帧本身就是音频，不需要类型位；视频解析与写入路径零改动
配置包 编码器 csd-0 作为配置包先发一次；断线重连后由 coordinator 重发 与视频的 SPS/PPS 处理保持一致，解码器重建后不需要重新协商
复用 MediaConnection 增加路径参数；media-relay 抽出通用 relay 并增加音频 sink 工厂。两条通道共用绑定校验、保活与重连实现 不复制一套连接生命周期，避免两套重连逻辑各自演化

4. 手机端实现

4.1 新增与改动文件

文件职责要点
android/.../audio/AudioCapture.kt AudioRecord 封装 48 kHz / 单声道 / PCM16；缓冲 20 ms；PTS 以 System.nanoTime() 为基准换算，与视频共用同一时钟起点；采集在独立线程循环读取。
android/.../audio/AudioEncoder.kt MediaCodec 编码 优先 audio/opus（48 kHz、单声道、64 kbps）；设备不支持时回退 audio/mp4a-latm（AAC-LC，同参数）；csd-0 作为配置包。
android/.../audio/AudioStream.kt 音频通道编排 持有 AudioCapture、AudioEncoder 与第二条 MediaConnection(/audio)；失败只影响音频，不中断视频。
android/.../media/MediaConnection.kt（改） 路径参数化 构造参数增加 path；不改变视频调用的行为。
android/.../media/MediaSessionCoordinator.kt（改） 生命周期 与相机同时启动/停止音频；重连时补发配置包；麦克风权限被拒或采集失败时降级为「仅视频」并把原因回传界面。

4.2 权限与降级

  • AndroidManifest.xml 增加 android.permission.RECORD_AUDIO；运行时与相机权限一起请求。
  • 权限被拒：会话继续、仅推视频，界面显示可读原因与「重新授权」入口；不因为麦克风失败中断视频。
  • 切后台/锁屏沿用既有前台边界：stop() 同一路径释放 AudioRecord 与 MediaCodec。

5. PC 端实现

5.1 新增与改动文件

文件职责要点
receiver/src/media-relay.ts（改） 音频通道 抽出通用 relay（视频/音频共用），音频 sink 指向 decode-host 的音频端口；绑定校验与保活不变。
native/decode-host/AudioDecoder.h/.cpp Opus / AAC → PCM float32 按配置包的 codec 选择解码器；swresample 统一到 48 kHz 单声道 float；断流时重置解码器状态。
native/decode-host/AudioRegulator.h/.cpp 自适应缓冲 目标缓冲 60 ms，按欠载/过载在 40–200 ms 间调整；目标值与时钟可注入，便于用假时钟验证。
native/decode-host/AudioSink.h/.cpp 输出抽象 接口 open / write / close / name；工厂按参数选择 WAV、默认设备或虚拟设备端点。
native/decode-host/WasapiSink.cpp WASAPI 共享模式渲染 目标端点由参数指定（默认系统默认播放设备）；事件驱动写；端点消失时关闭降级，不阻塞视频。
native/decode-host/WavFileSink.cpp 落 WAV 16-bit PCM，头部在关闭时回填；用于无驱动环境的确定性证据。
native/decode-host/main.cpp（改） 双通道接入 视频端口行为不变；新增音频监听端口与音频线程；参数 --audio-wav、--audio-device、--no-audio。

5.2 线程与缓冲

  • 音频解码在独立线程；regulator 决定喂给 sink 的节奏；视频读循环只做解析与投递，不做重采样与设备写入。
  • 环形缓冲满时丢最旧音频并计数，日志限频，避免刷屏影响视频日志。
  • 音频不可用（无解码器 / 无设备 / WAV 打开失败）时打印一条原因并继续视频，不退出进程。

6. 音频输出目标：用户自备虚拟声卡

本版不自研内核驱动、不做签名（D-012）：系统录音端点只能由内核音频驱动创建，而在开源、零预算的约束下无法取得微软签名。因此音频改为「探测用户机器上已装好的虚拟声卡，并主动输出到它」。

项内容
探测枚举 WASAPI 渲染端点；对每个候选寻找同一音频适配器下的采集端点（cable 类驱动的结构特征）；CABLE / VoiceMeeter / Line 1 等名称匹配只作兜底，避免写死厂商。
选择固定优先级：CABLE > VoiceMeeter > 其他成对端点；命中即用，不给用户选择框，界面只显示当前命中的设备名。
未命中音频关闭，界面显示原因与安装指引；视频完全不受影响。
运行中变化监听设备变化：跳板消失则关闭音频并显示原因；出现新的成对端点时可自动切换。
不打包不随包分发、不修改任何第三方虚拟声卡（再分发需授权）；只检测与使用。
可选监听双路输出（跳板 + 默认扬声器）默认关闭，开启后用户能直接听到手机端声音；纯用户态，无签名需求。

7. 验收标准

编号层级通过条件
AC-1协议/audio 通道未绑定前收到二进制被拒绝；绑定通过后正常收帧；帧头解析与视频共用同一实现且语义未变。
AC-2编码手机端默认输出 Opus，缺少该编码器时回退 AAC-LC；配置包在起流与重连后各发送一次。
AC-3手机链路采集与编码启动后，PC 端解出样本；断开重连后音频恢复，不需要重启 decode-host。
AC-4无设备验收--audio-wav 产物可播放，时长与样本数自洽（误差 ≤ 100 ms），内容可辨认。
AC-5跳板输出在装有受支持虚拟声卡的 Windows 上：启动后自动命中该跳板并输出音频，其采集端能收到手机麦克风声音（OBS 选中该采集端有电平、录制回看有声音）；未装时音频不可用并提示原因，视频正常。
AC-6不退化既有 Node 与 JVM 测试通过；OBS 仍能选 Artemis Camera 看到画面；APK 可构建。

8. 明确不做

  • 不写内核驱动、不做代码签名、不要求用户关闭 Secure Boot 或开启测试模式。
  • 不随包分发或修改任何第三方虚拟声卡。
  • 不改帧头语义，不引入音频类型位，不做协议版本协商。
  • 不做 APO、音效处理、降噪、回声消除。
  • 不做静音开关、音量控制、多声道、码率自适应。
  • 不改 DirectShow 过滤器；不动共享内存帧格式。
  • 不承诺 OBS 以外软件的兼容性。

9. 风险与回滚

风险应对回滚
音频通道与视频通道生命周期冲突共用 relay 与连接实现，路径参数化；音频失败只降级音频--no-audio 启动即回到纯视频行为
regulator 策略不当导致爆音目标缓冲可注入、可观测（欠载/过载计数）；先用 WAV sink 验证再上设备退回固定缓冲
设备编码器缺失（无 Opus）运行期探测编码器列表，回退 AAC-LC—
用户未安装虚拟声卡明确提示原因与安装指引；不把「无音频」写成通过—
端点结构或命名变化导致识别失败结构特征优先、名称兜底；单测覆盖未知端点提供手动指定端点的参数
第三方声卡被卸载或禁用监听设备变化，只关音频并提示—

10. 实施顺序与提交切分

  1. 通道层：/audio 路径参数化 + relay 复用 + 绑定校验测试（先红后绿）。
  2. 手机端：AudioCapture → AudioEncoder（Opus/AAC）→ AudioStream 接线 → 权限与降级。
  3. PC 端：AudioDecoder → WavFileSink（先跑通无设备验收）→ regulator → WasapiSink。
  4. 端点探测与路由：成对端点识别、固定优先级、无设备降级、设备变化监听、可选双路监听。
  5. 接线与回归：OBS 选跳板采集端验证；既有 Node / JVM 测试与视频冒烟。

一步一提交，便于回滚与审查；通道、手机端、PC 端、端点路由、接线不混在同一提交。
