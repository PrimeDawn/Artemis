结论

验收核心是「不退化」而非「新增」：手机端零 diff、配对主路径照旧、状态文案照旧；同时必须证明旧接收端真的消失，不能靠删测试凑绿。

硬规矩：禁止真实时长等待

本计划不允许任何按真实耗时编排的用例：72 小时、1 小时、65 分钟、10 分钟连续运行一律不得作为真实等待执行。时间相关断言只能通过假时钟推进（如 f.advance(72*60*60*1000)）在同一次测试运行内完成——现有 connection-manager.test.ts 的 72 小时用例本来就是这种做法，不需要真实等待。任何需要真实时间才能验证的结论，改为代码/状态机审查并标注「未实测」。

测试数据原则

尽可能少用 mock；非必要一律用真实数据：真实服务进程、真实 HTTP/TLS/WebSocket 连接、真实文件与真实密码学。只有在无法构造真实条件时才用桩，并在报告中写明原因。老用例里的假时钟（f.advance()）保留，因为不允许真实时长等待（见 D-005）。

  1. TC-01 至 TC-11 全部通过，无跳过掩盖。
  2. TC-12 模拟器通过；TC-13 真机通过。若真机不可用，该项记为 未测，并明确「手机端无感」只有模拟器与单元测试背书，不得宣称真机已验证。TC-12 模拟器通过即为手机端验收通过；不设真机门禁，真机若后续补测则另行登记，不改变本次结论。
  3. git diff --stat android/ 为空；若不为空，本 Spec 判定不通过（手机端改动违背无感目标）。
  4. 测试报告给出 43 → 41 的对照、4 条用例处置理由，以及残留引用扫描结果。
