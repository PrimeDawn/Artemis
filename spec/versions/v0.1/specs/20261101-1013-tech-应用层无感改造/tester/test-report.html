3. 端到端关键证据

仪器测试 PairingEndToEndInstrumentedTest 在真实服务上依次报告以下阶段，全部通过：

  • actual-tcp-probe-passed / actual-pinned-tls-probe-passed：手机能连到电脑，SPKI 固定校验通过
  • first-consent-visible：首次连接确认出现，测试点击「允许并记住」
  • connected-before-recreate：手机进入「已连接」，界面重建后仍是已连接且控制器实例不变
  • awaiting-service-restart → observed-actual-disconnect：电脑服务被真实终止，手机观察到中断并进入重连
  • reconnected-without-consent：服务重启（同 SPKI）后自动恢复，未再次弹出确认，trustedAt 不变
  • manual-stop-observed：点击「断开连接」后回到等待态，且本机信任被标记为抑制

另有手工截图与无障碍树确认手机界面显示「已连接 / 电脑：KurumiUMP / 断开连接 / 取消对这台电脑的信任」。

4. 未覆盖与偏差

控制页浏览器 e2e 已执行

tests/pairing-web-e2e.mjs 改用本机已安装的 Edge（PW_CHANNEL=msedge），4/4 通过：首次选择与已连接、忙碌拒绝、主动断开后不自动恢复、浏览器审计（无 console 错误、全部请求本地）。不再依赖 Chrome。

取消信任已在真机验证

在 Galaxy S24 上点击「取消对这台电脑的信任」，再从控制页选中同一台手机，App 重新弹出「允许这台电脑连接？」并要求一次确认，符合产品规则。

模拟器首次生成的 Keystore 竞态

全新安装后第一次运行 ConnectionInstrumentedTest 时，KeystoreDeviceIdentity 在生成密钥后立即读取证书得到 null，导致该轮 1 项失败；同一安装第二次运行 3/3 通过。结论：这是 API 29 模拟器首次生成密钥的时序问题，与本次改造无关（android/ 零改动），已记录为问题项。

mDNS 在模拟器不可用

模拟器收不到主机 mDNS 组播，测试通过项目既有的 discovery 回调桥接注入真实端点（real-endpoint-discovery-callback-bridge）。真实局域网 mDNS 发现不在本轮覆盖范围。
