结论

验收的真值只有一个：OBS 里能选到 Artemis Camera、能看到画面、录 30 秒回看有画面。其余用例都是为了让这个结论可复现、可定位。

1. 环境

项要求当前状态
编译器VS Build Tools 17.x，C++ 工作负载安装中（安装器自更新阶段）
Windows SDK10.0.26100随 Build Tools 安装
OBS33.x 64 位已安装
权限注册过滤器需要管理员需要用户/会话具备

2. 用例

编号用例步骤期望
TC-01构建powershell -File native/build.ps1退出 0；产出 ArtemisCamera.dll 与 synthetic-producer.exe
TC-02位数dumpbin /headers 查两个产物均为 x64
TC-03注册register.ps1 -Action register退出 0；HKCR\CLSID\{7E1F3A10-...} 与 InprocServer32 存在
TC-04设备类别查 HKCR\CLSID\{860BB310-5D01-11D0-BD3B-00A0C911CE86}\Instance 下条目存在本 CLSID，FriendlyName 为 Artemis Camera
TC-05OBS 枚举重启 OBS，添加「视频采集设备」列表中出现 Artemis Camera
TC-06OBS 预览选中设备，观察预览出现色条画面，不黑屏、不报错
TC-07帧号递增启动 producer，连续两次截图比较画面右下角帧号递增，说明帧来自共享内存
TC-08无 producer关闭 producer，观察预览输出黑帧但不卡死，OBS 不报设备丢失
TC-09录制回看录 30 秒，回放回看有画面
TC-10反注册register.ps1 -Action unregister 后重启 OBS退出 0；列表不再出现该设备；重新注册后恢复

3. 证据要求

类别形式
命令类用例日志含 Command:、Exit code:、ISO8601 时间戳，落在 tester/artifacts/test-logs/
注册表检查导出键值的命令输出原文，不手抄
OBS 类用例截图（枚举列表、预览画面、录制回放），存 tester/artifacts/test-logs/<run-id>/
帧号递增两次截图，文件名带时间先后

不使用 mock：所有用例都跑真实 DLL、真实注册表、真实 OBS。构建与注册的临时产物只落在 native/out/ 与系统注册表，测试结束后反注册清理。

4. 通过标准

  1. TC-01 至 TC-04、TC-10 命令类用例全部退出 0 且断言成立。
  2. TC-05、TC-06、TC-09 有截图且画面内容明确。
  3. TC-07 两次截图的帧号不同且递增。
  4. TC-08 描述清楚「无 producer 时的表现」，不要求有画面。
  5. 任何一项失败必须记录实际输出，不得以「环境问题」跳过而不留证据。

5. 失败处置

失败处置
编译失败转 spec-debugger，保留完整编译器输出
注册失败先确认是否管理员权限；权限不足记 env 类问题，不判产品失败
OBS 不枚举查注册表键是否完整、位数是否 64、OBS 是否重启
有设备但黑屏查引脚是否拒绝协商媒体类型、帧线程是否启动
帧号不递增查共享内存名、producer 是否真在写、writeIndex 协议
