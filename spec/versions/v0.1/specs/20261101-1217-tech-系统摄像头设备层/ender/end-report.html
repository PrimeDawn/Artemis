结论

Windows 上已经存在一个 OBS 能选、能出画、能录制的摄像头设备 Artemis Camera，画面来自共享内存。手机画面尚未接入，这条链路留待 SPEC-phone-media。

4. 实质决策

编号决策理由
D-001过滤器 + 共享内存 + 合成 producer先验证唯一稳定接缝，用户确认
D-002只做 64 位OBS 33 为 64 位
D-003逐用户注册（HKCU）UAC 无人值守时被取消，导致设备未注册

5. 遗留与风险

项影响建议
手机画面未接入产品核心功能未完成下一 Spec SPEC-phone-media 承接
单分辨率 720p30非 OBS 的程序请求其他尺寸会失败接真实帧时按手机输出做协商与缩放
无安装包换机器要手工拷 DLL 并注册后续单独开打包/安装 Spec
只在本机验证换机、升级、卸载未测随安装包 Spec 一并覆盖
测试计划 TC-08 描述过时计划写「输出黑帧」，实际保持最后一帧下次修订测试计划时修正

6. 经验

  • 对接第三方宿主（OBS）时，先做对照实验判断问题在谁身上。把 OBS 自带虚拟摄像头用同样方式配置，一次就证明了是我的集合写法错，而不是过滤器坏。
  • 设备注册位置影响可用性：写 HKCR 需要 UAC，无人值守时会静默失败，逐用户注册更稳。
  • DirectShow 协商细节（biHeight 符号、FORMAT_VideoInfo2）只能靠实测日志定位，不能靠文档推断。
