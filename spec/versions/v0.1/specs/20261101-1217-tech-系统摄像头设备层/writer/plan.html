实现计划：系统摄像头设备层

结论

分两步交付：先让 OBS 枚举到带画面的 Artemis Camera（过滤器内部合成帧），再接上共享内存与独立 producer。这样即使 IPC 出问题，也能立刻判断是过滤器还是帧源的问题。

2. 阶段一：可枚举的过滤器

  1. 实现 DllGetClassObject 与类工厂，CLSID 固定为 {7E1F3A10-2C4B-4D8E-9A55-3F0C1B7D9E21}
  2. 实现 IBaseFilter：EnumPins 返回一个输出引脚，QueryFilterInfo 返回 Artemis Camera
  3. 输出引脚只接受一种媒体类型：MEDIASUBTYPE_RGB32、1280×720、30fps；IAMStreamConfig 的 GetStreamCaps 返回同一项
  4. 帧线程每秒 30 次填充 IMediaSample：画 8 条色条，右下角叠加帧号
  5. DllRegisterServer 写两份注册表：HKCR\CLSID\{...}\InprocServer32（DLL 路径、ThreadingModel=Both）与 HKCR\CLSID\{...} 下的 FriendlyName/FilterData，并把 CLSID 登记到 CLSID_VideoInputDeviceCategory

3. 阶段二：共享内存帧源

3.1 共享内存布局

偏移字段说明
0magic (0x41435456 即 "ACTV")拒绝非本协议映射
4version = 1不兼容即视为无帧
8width = 1280—
12height = 720—
16stride = 5120width*4
20format = 1（RGB32）枚举
24writeIndex (uint64)奇数=正在写，偶数=稳定
32frameIndex (uint64)producer 自增
40timestampUs (uint64)producer 侧时间
64frame[2][5120*720]双缓冲，按 writeIndex 选择稳定块

映射名固定为 Global\ArtemisCameraFrames，过滤器以只读方式 OpenFileMapping(FILE_MAP_READ)；producer 不存在时过滤器输出黑帧并继续出流，不阻塞。

3.2 写入协议

  1. producer 选目标块 b = (frameIndex % 2)，writeIndex++（变奇数）
  2. 写像素与 frameIndex/timestampUs
  3. writeIndex++（变偶数，标记稳定）
  4. 过滤器读 writeIndex 两次，相等且为偶数时才拷该块，否则沿用上一帧

4. 构建与注册

命令期望
powershell -File native/build.ps1退出 0，产出 ArtemisCamera.dll 与 synthetic-producer.exe
powershell -File native/register.ps1 -Action register退出 0；需要管理员
powershell -File native/register.ps1 -Action unregister退出 0，CLSID 键被移除

注册脚本不静默吞失败：regsvr32 非 0 或注册表项缺失都返回非 0。

5. 验收

  1. 构建退出 0，两个产物存在且为 64 位（dumpbin /headers 显示 machine x64）
  2. 注册后 HKCR\CLSID\{7E1F3A10-...} 与 CLSID_VideoInputDeviceCategory 下均存在对应项，FriendlyName 为 Artemis Camera
  3. OBS「视频采集设备」列表出现 Artemis Camera，选中后有画面
  4. 启动 producer 后画面出现帧号递增；不启动 producer 时仍有黑帧，不卡死
  5. 用 OBS 录 30 秒，回看有画面
  6. 反注册后 OBS 列表不再出现该设备；重新注册后恢复

6. 风险与回滚

风险应对
没有 BaseClasses（streams.h）本计划直接实现 IBaseFilter/IPin 最小集合，不依赖 SDK Samples
注册需要管理员脚本显式提示；失败返回非 0，不伪装成功
OBS 缓存旧设备列表注册后重启 OBS；验收前先关闭 OBS
GPLv3 参考实现只参考结构，不复制源码

回滚：反注册并删除 native/out/ 即可，不涉及系统驱动，无残留风险。
