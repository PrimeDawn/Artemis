3. OBS 接入的关键发现

手写场景集合时 OBS 报 DecodeDeviceId failed。做了对照实验：把 OBS 自带的 Virtual Camera 用同样方式写进去，**同样失败**，说明问题在集合写法而不在过滤器。

改用 OBS 界面添加源后，读出 OBS 自己保存的 video_device_id：

Artemis Camera:@device#3Asw#3A{860BB310-5D01-11D0-BD3B-00A0C911CE86}\\{7E1F3A10-2C4B-4D8E-9A55-3F0C1B7D9E21}

即「友好名 + 冒号 + 设备路径（: 转义为 #3A）」，不是 base64。同时 OBS 要求设备在 VideoInputDeviceCategory\Instance 下带 DevicePath。

另一个真实缺陷：OBS 传给 IAMStreamConfig::SetFormat 的 biHeight 是正值（bottom-up），过滤器原先只接受负值，导致 VFW_E_INVALIDMEDIATYPE。改为两种符号都接受后画面立即出来。

4. 注册方式变更

原先写 HKEY_CLASSES_ROOT，每次注册都要 UAC。实测 UAC 在无人值守时会被取消，导致设备处于未注册状态。改为写 HKCU\Software\Classes\CLSID：

  • 无需管理员，注册与反注册都能在普通会话完成
  • OBS 与 DirectShow 枚举均能看到该设备（探针实测 device: Artemis Camera）
  • 影响范围收敛到当前用户，回滚只需反注册
