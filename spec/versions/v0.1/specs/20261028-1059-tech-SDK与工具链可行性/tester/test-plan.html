1. 验收标准与当前状态

本文件是测试计划，所有用例尚未执行。独立测试阶段尚未开始；executor聚焦证据见实现总结，本计划不登记最终通过。本轮已执行16项必测，三个设备条件项未实测，具体结论见测试报告。本Spec构建/来源/服务层通过条件：TC-01至TC-16全部有本轮真实证据并通过；运行条件用例TC-D1至TC-D3按实际设备执行，没有条件时标not-run及原因。

缺设备不把本Spec已有的构建层证据作废，但不得宣布JNI、Android10或16KB运行兼容已通过，也不能据此通过v0.1音视频链路或正式产品验收。任何必需构建/服务项失败都不通过；测试不直接修复产品代码。

4. 测试方法与所有权

  • spec-executor拥有receiver/test/config.test.ts的聚焦测试。先建立能编译的骨架，再让断言因预期行为不成立而失败；编译失败、找不到命令和空断言不算有效RED。
  • spec-tester拥有tests/receiver-smoke.mjs和Android设备侧SmokeTest，独立执行真实HTTP/子进程及条件设备验证；不修改executor的单元测试来制造通过。SmokeTest使用AndroidJUnitRunner 1.7.0及ext.junit 1.3.0的JUnit4入口。
  • 构建、依赖、许可证和静态对齐采用实际工具输出；不为声明式配置、常量字段或静态文字额外制作镜像实现的测试。
  • 本轮关键行为应覆盖已定义的所有成功、失败与退出路径；不对构建配置和静态界面机械套用80%代码覆盖率阈值。

5. 执行命令与证据生成

从项目根执行；每轮独立runId，原始日志与JSON只能由实际运行自动生成。以下是实施后的验证入口，当前未执行。

$SpecDir = "spec/versions/v0.1/specs/20261028-1059-tech-SDK与工具链可行性"
$RunId = [DateTimeOffset]::UtcNow.ToString("yyyyMMdd-HHmmss")
$Logs = Join-Path $SpecDir "tester/artifacts/test-logs/$RunId"
New-Item -ItemType Directory -Path $Logs -Force

powershell -NoProfile -File scripts/verify-toolchain.ps1 -ReportPath "$Logs/environment.json"
.\android\gradlew.bat -p android --no-daemon clean :app:assembleDebug
.\android\gradlew.bat -p android --no-daemon clean :app:assembleDebug
python scripts/verify-native-libs.py --apk android/app/build/outputs/apk/debug/app-debug.apk --report "$Logs/native-check.json"
# zipalign从SDK build-tools/36.0.0目录调用，路径由实际SdkRoot提供；不依赖全局PATH
npm --prefix receiver ci --ignore-scripts
npm --prefix receiver test
node tests/receiver-smoke.mjs --report-dir "$Logs/receiver"

# 有相应设备时才运行，并保存实际结果：
.\android\gradlew.bat -p android connectedDebugAndroidTest

测试运行器为每条命令采集stdout、stderr、退出码、开始/结束时间、源SHA、工具版本及产物SHA256；必须等待子进程结束。禁止在运行后手填success或补造JSON。命令失败保留原始输出，交回TeamLead判定是否启动debug角色。

HTTP集成运行器接收--report-dir PATH，缺参退出非零；使用临时端口与带超时的真实请求；finally关闭所有自建进程。设备标识在日志中脱敏，不保存完整设备序列号、配对信息、token或个人路径。

关闭幂等和释放监听由真实RunningReceiver.close及重绑端口验证；CLI可另用真实终端Ctrl+C观察正常退出。Node.js说明Windows信号行为不同，自动化强杀结果不作为SIGINT/SIGTERM处理通过的证据，未具备终端条件时该细项列未实测。参见Node.js官方信号说明。

6. 日志与审计要求

  • 环境/SDK缺项、依赖校验失败、服务启动成功、无效端口、端口占用和正常关闭都应留下可追溯记录。
  • 仅在测试完成后生成tester/test-report.html及completion.report.v1报告，criteria从权威台账原文读取，绑定真实源SHA；不手工勾选尚未执行的用例。
  • 设备未连接、未授权或不存在16KB环境时，使用not-run并写具体原因；不尝试规避设备授权或把静态检查升级为运行结论。
  • 本轮不触发媒体采集、LAN外部服务、账号或真实用户数据；本地诊断服务只绑定127.0.0.1。

7. 风险、失败处理与复测

失败时记录用例、输入、预期、实际、退出码及证据位置，交TeamLead。需要test-debug修复循环时先确认轮数与无进展预算；未确认预算前不自行反复修复。版本组合实质变化须先修订实现计划和本测试计划。

报告浏览器file协议预览受当前工具策略限制，本轮只做HTML结构、引用路径、导航和元信息检查；不据此宣称视觉渲染验证通过。产品设备UI验证仍由条件设备用例承担。

设备补测执行入口

原TC-D1至D3验收不变。新增tester拥有的tests/android-runtime-smoke.py执行实际安装、启动、JNI与本应用界面审计；--skip-install先核对设备上两个APK哈希。集成汇总器接受--runtime-report，验证实际设备条件、相同APK哈希及证据文件引用；本轮补测结果见测试报告。屏幕解锁由用户操作，锁屏不被当作应用UI。

条件设备执行补充

原TC-D2/D3已允许对应模拟器环境，验收条件未改。本轮由官方API29默认镜像与API36 Google APIs 16KB镜像执行，先断言真实API及PAGE_SIZE，再安装、观察界面及运行JNI；tests/collect-runtime-matrix.py将三环境运行绑定到同一APK及未变化的必测输入。完整结果见测试报告。
