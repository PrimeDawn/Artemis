草稿一：RELRO静态检查按实际保护范围判断

类型与权重：经验，重大；关联ELF布局、链接器保护范围及APK验证，适用于以后引入或升级原生依赖。关键词：Android、16KB、ELF、GNU_RELRO、PT_LOAD。

困境：仅检查RELRO段末端取模，会误拒绝覆盖完整独立LOAD并包含填充的布局。策略：检查64位LOAD对齐和地址/偏移一致性，再判断RELRO的实际保护范围；允许覆盖独立LOAD及其填充，拒绝保护范围覆盖其它可写段的情况。分别保留共享段失败、独立段成功及填充越界失败用例。理由与边界：保护范围决定是否误保护数据；ELF检查还需配合最终APK ZIP检查，实际16KB加载继续由设备验证。证据：scripts/verify-native-libs.py、scripts/tests/test_verify_native_libs.py、executor/artifacts/tdd/中的RED/GREEN以及本轮9项回归和native-apk.json。

草稿二：Windows CLI关闭以真实控制台事件形成证据

类型与权重：经验，重大；涉及测试控制台、进程退出、日志和端口生命周期，适用于后续Windows服务测试。关键词：Windows、Ctrl+C、Node.js、控制台、进程退出。

困境：PTY传输Ctrl+C导致外层会话中断，或强杀子进程，都不能证明应用执行了SIGINT关闭逻辑。策略：测试自建隐藏独立控制台，向自己的Node进程发送实际CTRL_C_EVENT；同时断言receiver_stopped、退出0、无强制清理及端口可重新绑定，保留超时和退出审计。理由与边界：联合观察信号、应用事件和OS资源释放，能区分真实关闭与测试夹具清理。该经验针对本次Windows/Node组合，不替代其它平台实测。证据：tests/windows-cli-signal.py、tests/receiver-smoke.mjs及本轮receiver/signal-summary.json。
