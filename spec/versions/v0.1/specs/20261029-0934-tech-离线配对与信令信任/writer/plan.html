3. 设计方案

3.1 信任与进程边界

保留旧健康服务入口；新增npm --prefix receiver run pairing。新入口读取显式E盘身份目录与用户选择的本机RFC1918 IPv4，启动127.0.0.1控制HTTP/WS以及该LAN地址的HTTPS/WSS两个监听。页面与脚本全部本地提供，不把控制API绑定到LAN或0.0.0.0。

本机控制会话Cookie+CSRF、严格Host和Origin共同约束控制操作及浏览器WS。浏览器接收页无需访问LAN自签名端口；手机仅连接LAN加密端口。该本机边界不防御已能以当前用户身份执行代码的恶意软件，不能宣传成端点安全隔离。

先由现有OpenSSL生成RSA2048/SHA256、30天有效期、含所选IP SAN的自签名叶证书。身份文件读入后核对key匹配、有效期与SAN；私钥目录只给当前用户，不写仓库或证据。身份默认不覆盖；显式Rotate先停止服务、让全部会话失效再重新配对。无需安装CA到系统或浏览器。

连接串格式固定为artemis://pair?data=base64url(UTF-8 JSON(PairInvite))，最大4096字节。安卓只从操作者导入的信息取得预期指纹；TLS握手中先核对单叶证书DER的SHA256、自签名与有效期，并保持OkHttp默认主机名核验；不提供信任所有证书、HostnameVerifier恒true、明文或公网回退，自动重定向关闭。

3.5 状态与错误

挑战：issued→consumed/expired，重新生成时旧挑战立即无效；同一挑战并发claim仅一个成功。会话：paired→revoked/expired，关闭进程也失效。凭据仅内存，原码/票据只在响应和操作者页面短暂存在，原值不记日志。比较等长摘要使用timingSafeEqual。

发送端与接收端均到位后由服务端签发新epoch并发送ready；任一端断开则旧epoch作废并通知peer-disconnected，另一次双方到位产生新epoch。单个会话最多一个sender、一个receiver。撤销/过期主动关闭双方并删除待接收票据；不自动重新配对或恢复采集。

业务错误码固定：E_INPUT/400、E_AUTH/401、E_ORIGIN与E_CSRF/403、E_NOT_FOUND/404、E_CONFLICT与E_REPLAY/409、E_EXPIRED/410、E_TOO_LARGE/413、E_RATE_LIMIT/429、E_INTERNAL/500；证书与连接失败在客户端映射E_TLS_IDENTITY、E_TLS_EXPIRED、E_TLS_HOST、E_NETWORK。HTTP升级前按同规则拒绝；已升级协议违例close1008，超长1009，撤销4001、过期4002、重复连接4009。

HTTP配对body4096字节，WS最大65536字节；认证首帧512字节/3秒；连接每秒最多20业务帧，单epoch最多128条ICE、1024个去重ID，越界拒绝。挑战错误5次作废；配对尝试按地址每分钟20次，限速表最多256项/60秒。心跳30秒，90秒无响应关闭。仅记录事件、关联ID和错误码，不记录URL查询、请求体、Cookie、Authorization、连接串、票据、私钥、SDP/ICE正文。

3. 设计方案

3.1 发现与用户路径

PC以DNS-SD/mDNS发布_artemis._tcp.local.，指向本机选定RFC1918 IPv4上的HTTPS/WSS端口；Android用系统NsdManager发现并解析，不新增手机端HTTP服务器。手机自动建立受限presence连接，因此PC控制页能列出打开App的手机。发现TXT只携带v=2、pcId、公钥及显示名，不含秘密。设备名与IP均不是身份或授权依据。

电脑控制页为127.0.0.1 HTTP/WS，手机入口为所选LAN地址HTTPS/WSS，保留原健康服务入口；新增pairing入口，不绑定控制API到LAN或0.0.0.0。默认端口3000/3443。PC使用bonjour-service纯Node实现，无需安装系统Bonjour服务。Android29..36走兼容NSD接口，解析串行化，跟随网络变化重建发现；低版本按SDK扩展能力正确获取/释放MulticastLock。

  1. 启动电脑服务并打开控制页；打开手机App，自动发现PC并发送仅含公开身份的hello。电脑列出“未信任/已信任、可连接/离线/忙碌”。同名设备显示短ID以区分。
  2. 电脑点击未信任手机的“连接”，手机显示“允许这台电脑？”及电脑名/身份摘要。用户允许后，两端保存信任；拒绝则保持未授权，不反复弹窗。
  3. 已信任手机点击连接时自动完成身份挑战，无二维码、连接串或再次确认；同一手机只允许一台活动电脑，不静默抢占。
  4. PC记住被选择的设备及desired=connected意图；App重开、地址变化或服务重启后自动恢复该选择。首次尚未选择或主动断开后，只显示设备，等待鼠标选择，不自动连接其它设备。
  5. 接收验证页沿用本机单次票据入口；票据期限只约束未消费的首次认证，已认证接收连接不继承票据TTL。

服务发现不扫描公网或整个私有网段；多网卡只使用所选LAN接口。不改防火墙/路由器/代理，若组播受限显示“未发现设备/局域网隔离”，不默默切到云端或要求正常用户扫码。每端最多跟踪8个PC候选、PC最多32条未选中presence连接，状态表均有界。

3.2 身份、首次确认与存储

两端使用稳定ECDSA P-256身份，ID为SPKI DER的SHA256（32字节base64url，无填充，43字符）。手机私钥在Android Keystore，关闭每次使用生物认证要求；受信电脑ID/公钥在应用私有noBackup目录。PC私钥、trust-store.json与selection.json放显式E盘私有数据目录，限定当前用户ACL；仅存公开对端身份和选择，不把永久Bearer令牌作为设备信任。

首次发现的公钥未经带外认证。用户在自有可信家庭/工作室LAN中进行首次确认，属于TOFU信任选择；不能宣称仅凭广播和设备名能抵抗首次主动中间人。提示显示电脑名及身份摘要，不要求扫码/输入配对码；以后使用已记住的公钥，发现记录换钥/冒名不能静默覆盖或取得权限。取消信任、卸载清数据或身份真正丢失后重新首次确认。

Android先核对TLS叶证书SPKI与当前候选/已记住的PC身份、自签名、有效期，并保持OkHttp默认主机名/SAN核验；无trust-all、恒true主机名校验、明文或公网回退，禁自动重定向。已知PC的发现记录与存储公钥不一致立即拒绝并显示身份变化，不自动首次确认覆盖旧记录。

PC自签名叶证书仍有正常有效期（30天），但设备信任绑定稳定公钥而非某张短期证书。服务启动时、IP变化时及每日检查证书，余期不足7天或SAN变更则用同一私钥自动续签；通过HTTPS setSecureContext更新后续握手，不关闭现有连接，不要求重新信任。过期/错误SAN仍拒绝，不通过忽略验证达到“无限”。失败时保留现有连接、显示诊断并重试续签；信任私钥轮换必须显式处置。

3.5 无固定到期、保活与重连

信任与活动连接expiresAt固定null，store不得存在1小时/空闲TTL关闭逻辑。WebSocket心跳30秒；连续90秒无响应判定socket失活并进入reconnecting，这属于故障探测，不是活动连接到期。无需业务消息才能保活。重连按1/2/4/5秒上限加0..250ms抖动重复尝试，不设最大次数或总时长；网络恢复回调立即触发一次，不建立并发重试。网络正常后目标10秒内恢复信令，实际测量计时。

已选设备身份与连接意图长期保存；进程重启后读取，地址由服务发现重新解析，IP变化不改变信任。新的已授权双端会话使用新sessionId/epoch，丢弃旧SDP/ICE并要求媒体层重新协商；本Spec只验证fixture消息，不声称媒体已恢复。连接控制器由Application级容器持有，Compose重组、配置变化或退出验证子页不主动断线；“断开/取消信任/显式退出App”才停止对应意图。后台/锁屏时Android系统可能限制网络，本Spec不虚构永久后台保证，也不以dataSync服务冒充不限时方案；真实相机/麦克风前台服务由媒体Spec结合权限设计。

单活动sender/receiver；断线自动认证只能恢复原被选设备，不允许另一台手机/电脑顶替。WS最大65536字节，hello2048字节/3秒，业务20帧/秒，128个ICE/epoch、1024去重ID、限速地址表256项。认证/首次请求、接收票据可以有短期防重放期限，消费后与活动连接期限分离；不把内部安全nonce的时效暴露为重复配对流程。
