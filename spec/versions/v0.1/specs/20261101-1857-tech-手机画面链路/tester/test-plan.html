结论

真值只有一条：OBS 里的画面必须是手机正在对着的东西。其余用例保证这条链路可重复、可定位失败点。

1. 环境

项要求当前
设备Android 设备，含 Camera2模拟器可用；真机 Galaxy S24 已授权
OBS33.x，已注册 Artemis Camera已就绪
FFmpeg预编译 shared 包下载中
网络手机与 PC 同一局域网需实测

2. 用例

编号用例期望
TC-01Kotlin 单元测试（帧头编解码）12 字节帧头往返一致，标志位正确
TC-02decode-host 构建退出 0，产出 exe，能加载 FFmpeg DLL
TC-03解码进程接收首包收到 CONFIG 后建立解码器，日志可见
TC-04共享内存写入解码进程运行后，探针能读到非零帧号递增
TC-05OBS 显示手机画面画面内容与手机取景一致，可辨认
TC-06帧率与延迟OBS 统计接近 30fps；记录端到端延迟实测值
TC-07手机断开OBS 保留最后一帧，不崩溃、不冻结
TC-08重新连接画面恢复，无需重启 OBS 或解码进程
TC-09回滚停掉解码进程后回到合成画面

3. 证据要求

  • 命令类：日志含 Command:、退出码、ISO8601 时间戳
  • 画面类：OBS 截图，须能看出与手机取景一致（同一物体/同一角度）
  • 延迟：记录测量方法（如手机拍秒表、OBS 同屏对照）与实测值，不允许估算后当作实测

不使用 mock：全程真实手机、真实 TLS 连接、真实解码进程、真实 OBS。

4. 通过标准

  1. TC-01～TC-04 全部通过且退出 0。
  2. TC-05 有截图且内容可辨认为手机取景。
  3. TC-07 有断流前后两张截图。
  4. TC-06 给出实测延迟数值与测量方式。

5. 失败处置

现象先查
OBS 仍是色条解码进程是否在写共享内存；探针读帧号是否变化
绿屏/花屏像素格式与 stride；sws_scale 目标格式是否 BGRA
帧率远低于 30编码码率、WS 转发是否阻塞、解码是否软解瓶颈
断流后 OBS 异常过滤器在无新帧时的行为（应保留最后一帧）
