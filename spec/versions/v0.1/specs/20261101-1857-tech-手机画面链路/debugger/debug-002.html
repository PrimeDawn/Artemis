缺陷诊断：媒体绑定被拒

类型 debug 编号 debug-002（I-005） 角色 spec-debugger 分支 tech/spec-20261101-1857-phone-media ← dev 创建 2026-11-01 修订 r1（2026-11-01）
结论

媒体连接把应用包名当成了设备标识发给服务端，与会话里的真实设备 ID 不一致，绑定校验按设计拒绝。

1. 现象

{"name":"media_bind_rejected","requestId":"","code":"E_INPUT"}

媒体连接已能被服务端接收（upgrade 成功），但首条绑定消息未通过校验，连接被关闭，解码进程仍无 media channel connected。

2. 定位

检查点结果
服务端校验条件（authorizeMediaHello）要求 pcId、deviceId、sessionId 与会话完全一致
客户端发送内容pcId 正确；sessionId 正确；deviceId 传的是 context.packageName
会话中的 deviceIdmanager.activeDevice()，即手机身份 ID（43 字符 base64url）

两者永远不可能相等，因此每次绑定都被拒。

3. 根因

MediaSessionCoordinator.start 组装 MediaConnection 时，设备标识位置复用了 context.packageName。包名是 io.github.primedawn.artemis，与身份 ID 无关。

4. 修复方案

  1. ArtemisApplication 暴露 deviceId（来自 identity.peer().id）
  2. MediaSessionCoordinator.start 增加 deviceId 参数并传给 MediaConnection
  3. MainActivity 传入 app.deviceId
