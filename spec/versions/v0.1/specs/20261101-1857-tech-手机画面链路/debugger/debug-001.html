缺陷诊断：媒体连接未到达服务端

类型 debug 编号 debug-001（I-004） 角色 spec-debugger 分支 tech/spec-20261101-1857-phone-media ← dev 创建 2026-11-01 修订 r1（2026-11-01）
结论

媒体连接用默认 OkHttpClient() 建立 TLS，未复用配对时的证书固定，服务端自签名证书被系统信任库拒绝，握手失败，因此服务端连 upgrade 请求都收不到。

1. 现象

观测点实际期望

手机相机logcat 中 CamX 已在出帧，相机确实打开相机打开

2. 复现步骤

  1. 启动接收服务（3443 / 控制 3000）与解码进程（3450）
  2. 手机安装 App 并启动，完成首次配对
  3. 控制页批准连接，手机进入「已连接」
  4. 观察接收服务与解码进程日志：两边都没有媒体通道建立的痕迹

3. 定位过程

假设验证方式结论
媒体连接根本没发起（协调器未启动）相机已打开且 ensureCameraThen 在会话建立后触发，说明 media.start 已执行排除
服务端路由问题pairing-server 的 upgrade 按路径分流，/media 分支存在排除
TLS 握手失败服务端连 HTTP 层 upgrade 都没收到；客户端用 OkHttpClient() 默认信任库，服务端是自签名证书命中

4. 根因

配对用的控制连接通过 pinnedClient(pc) 建立，使用 PinnedTrustManager 按 SPKI 校验服务端证书。而媒体连接在 MediaSessionCoordinator 里直接 OkHttpClient()，走系统 CA，自签名证书校验必然失败，握手阶段即中断，请求到不了服务端。

5. 修复方案

  1. 在 PinnedTrustManager.kt 增加 pinnedClientFor(spki: ByteArray)，复用同一套固定逻辑
  2. ConnectionUiState 增加 spki 字段，由 ConnectionController 在会话建立时填充
  3. MediaSessionCoordinator.start 接收 spki，用 pinnedClientFor(spki) 建连
  4. MainActivity 把 state.spki 传入
