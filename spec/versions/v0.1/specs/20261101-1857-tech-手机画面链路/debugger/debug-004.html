缺陷诊断：媒体通道断开后不恢复

类型 debug 编号 debug-004（I-007） 角色 spec-debugger 分支 tech/spec-20261101-1857-phone-media ← dev 创建 2026-11-01 修订 r2（2026-11-01）
结论

三个独立原因叠加：手机端没有重连策略；接收服务在解码进程消失后不关闭手机连接；手机端只依据 send() 返回值判断连接状态，对端已消失仍继续发送。

1. 现象

解码进程退出后重新启动，手机仍显示「已连接」，但共享内存不再更新，OBS 画面停在最后一帧；必须重启手机 App 才能恢复。

2. 定位过程与根因

层次观测根因
接收服务解码进程消失后手机连接仍保持，日志只有 media_upstream_error转发端收到上游错误后只记日志，不关闭手机侧 socket
手机端重连没有任何重连尝试MediaSessionCoordinator 只在连接状态变化时启动，媒体通道自身没有重连策略
存活判断服务端已记录 media_upstream_lost，手机仍在 frames sent ok=truesend() 只写入本地缓冲即返回 true，不能代表对端存活
重连后画面新连接建立但解码端 frames=0编码器只在启动时发过一次 SPS/PPS，新解码器没有参数集
绑定顺序服务端记录 media_binary_before_bind重连时 socket 在 newWebSocket 就赋值，帧可能先于绑定消息发出

3. 修复方案

  1. 接收服务：上游 error/close 时关闭手机连接，日志 media_upstream_lost
  2. 接收服务：绑定后每 2 秒发一条心跳文本 {"t":"ka"}
  3. 手机端：心跳看门狗，超过 6 秒无服务端消息即取消连接并重连，间隔 1→5 秒递增
  4. 手机端：缓存最近一次配置帧，重连就绪后先补发，再请求关键帧
  5. 手机端：socket 只在绑定消息发出后赋值，避免二进制帧先于 hello
