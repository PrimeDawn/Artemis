验收判定口径

本 Spec 的通过标准是「只按 README 装两个包就能用」：安装包在未装 Node、未装 Git 的账户下安装成功，OBS 能枚举 Artemis Camera 并录出手机画面，卸载后注册项与程序目录干净消失；APK 能通过 apksigner 校验。任何一项靠「本机恰好装过」才通过，都判不通过。

覆盖率要求

  • 功能覆盖：§2.1 的 FR-001 至 FR-007 全部有用例；AC-1 至 AC-8 全部有用例或明确引用既有 Spec 的证据。
  • 失败路径覆盖：端口占用（TC-10）、缺 keystore（TC-05 边界）、导出泄漏（TC-11）、卸载时进程占用（TC-09 边界）四条必须有实际执行记录。
  • 不以静态检查替代：AC-3/AC-4/AC-5 必须实装实跑；只有 TC-14 允许以配置与路径断言替代，且必须在报告中注明原因。

日志与审计要求

关键路径可观测性

  • 证书签发：日志需含「签发/复用」二选一、证书到期时间、SAN IP；不得记录私钥内容。
  • 服务拉起：托盘日志需含子进程 PID、使用端口、LAN IP、数据目录。
  • 过滤器注册：安装器日志需含 regsvr32 退出码；注册后用注册表读取 FriendlyName 作二次确认。
  • 导出：脚本需打印纳入/排除条目数与目标路径；-Verify 失败时逐条列出违规路径。

端侧审计日志

  • 证据目录：tester/artifacts/test-logs/<YYYYMMDD-HHMM>/，每个用例一个 .log，原始格式不转 HTML。
  • 每条日志必须含命令、退出码与 ISO8601 时间戳（沿用 spec-end 的契约检查口径）。
  • 安装/卸载证据额外保存注册表导出与目录清单；录制证据保存 mp4 与其抽帧亮度输出。
脱敏

不得保存 keystore 口令、私钥 identity-key.pem 内容、手机序列号明文或完整 MAC 地址。

测试环境要求

  • Windows 11 x64（本机 10.0.26200），OBS 33.0.1，Inno Setup 6（需先安装到 E:\Dev\Artemis\tools）。
  • Node 24（构建期使用；验收期不得依赖 PATH 中的 node）。
  • Android 侧：JDK 17、SDK 36、Build Tools 36.0.0、release keystore（不入库）、apksigner（Build Tools 自带）。
  • 手机 SM-S9210（RFCX10MCR8F），与 PC 同一局域网；VB-CABLE 不安装（按 D-013 验证降级路径）。
  • 验收前需备份并清理现有开发版：记录当前 CLSID 键、备份 %LOCALAPPDATA%\Artemis\data，再反注册与删除程序目录。
风险

TC-08 依赖手机现场接入。若测试时手机不可用，只能执行到 AC-3 并通过注册表断言证明设备已注册，AC-4 必须记「未实测」而不是「通过」——这一点与 docs/validation-followups.md 的历史口径一致。
