4. 遇到的问题

风险：测试阶段回修的两个缺陷（I-011 / I-012）

①卸载器先删文件后杀进程，服务运行中卸载会残留 7 个被占用的可执行映像——改为 [Code] CurUninstallStepChanged(usUninstall) 先停进程、等待释放再反注册；②端口被占用时只留一句「service exited」，且 fwprintf 让中文变问号——改为启动前 Winsock 独占探测并按 UTF-8 输出。两处均已复测通过，细节见 tester/test-report.html §3。

注意：npm test 永不退出

接收服务全量测试会挂死。根因是 media-relay.ts 的保活 setInterval 没有 unref()：生产环境由服务器 socket 维持进程，但单测里没有其它句柄，进程就一直不结束。上一轮收尾是靠 --test-force-exit 绕过的，而该参数在 Windows 上会让 server.test.js 撞上 libuv 断言 !(handle->flags & UV_HANDLE_CLOSING)。解决方案：给定时器加 unref()，恢复标准 node --test。

注意：托盘拉起子进程失败时留下孤儿

父进程被强杀后 artemis-decode-host.exe 仍在运行，会占住共享内存与音频设备。解决方案：两个子进程加入同一个 Job Object（JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE），托盘退出即整体回收；实测强杀后残留为 0。

注意：网卡选择选中了代理虚拟网卡

首次 --selftest 返回 198.18.0.1（Clash/WARP 的保留网段），而接收服务只接受 RFC1918 地址，启动必然 E_CONFIG。解决方案：选择逻辑改为「默认路由所在网卡的私有地址 → 任意网卡私有地址 → 默认路由地址」三级回退。

注意：全新账户上数据目录建不出来

%LOCALAPPDATA%\Artemis 这一层在干净账户上不存在，CreateDirectoryW 直接失败（父目录缺失）。解决方案：改用 SHCreateDirectoryExW 逐级创建。

风险：本机沙箱 ACL 让安装包「跑不起来」

在本会话创建的目录（如仓库内 dist\）会带一条 Everyone:(CI)(DENY)(DC) 的继承 ACE，Inno 的加载器在该目录下无法解包，报 Setup was unable to create the directory …\is-XXXX.tmp 并以退出码 1 结束——同一个 exe 复制到 %TEMP% 后运行正常。这是本机沙箱写出的 ACL 造成的，与安装包本身无关；用户从 Release 页面下载的文件不带该 ACL。安装验证因此改为从 %TEMP% 副本执行。

5. 与设计方案的偏差

关键决策：licenses/FFmpeg-GPL.txt 改为构建时生成

plan 的文件清单把它列为新建文件。实际做法是构建脚本从 FFmpeg 发行包的 LICENSE.txt 复制进安装包（仓库里只提交 licenses/THIRD-PARTY.md）。原因：许可证原文属于上游产物，手工复制进仓库既容易过期又多一份副本；由构建步骤取当前实际使用的 FFmpeg 构建的许可证，分发义务才真正对应得上。

关键决策：stage 只装生产依赖

plan 未细化。首次构建把 node_modules 整体复制，安装包 66.4 MB 且带上了 typescript、@types 等构建期包。改为在 stage 内用 npm ci --omit=dev 单独落依赖后，安装包降到 63.4 MB。

关键决策：Artemis.exe 用 GUI 子系统 + 按需附加控制台

托盘程序若是控制台子系统，双击时会闪一个黑框。改为 /SUBSYSTEM:WINDOWS + wWinMain；--selftest/--console 时若输出未被重定向再 AttachConsole，既保证双击无黑框，也保证自动化能拿到 stdout。

6. 后续建议

  • 「OBS 实际采集画面」与「卸载时服务正在运行」两条需要手机与真实采集场景，交 spec-tester 执行；本机只验证到注册表与服务启动。
  • release keystore 目前只在本机（android/artemis-release.jks + android/signing.properties，均已 gitignore）。后续要长期发版就必须备份它，否则无法覆盖升级已安装的 APK。
  • dist\ 因沙箱 ACL 无法直接运行安装包，建议在本会话外（资源管理器双击或普通终端）复验一次安装体验。
  • Smart App Control 会把未签名安装包拦下来，README 已写明处置方式；正式对外发布前如有预算，代码签名是唯一根本解。
