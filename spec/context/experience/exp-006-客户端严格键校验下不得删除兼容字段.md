# 客户端严格键校验下不得删除兼容字段

## 困境

服务端重构时，某个字段（本次是 `epoch`）已无内部用途，最自然的做法是从下发的消息里删掉。但客户端若对消息键集合做严格校验，缺键会被判为协议错误并断开连接。

## 策略

先确认客户端是否做 `exact` 式键校验（本项目为 `WireCodec.exact` 与 `DeviceClient` 的 `waiting/ready` 分支）。若做，则保留字段并固定为 `null`，只清理服务端内部状态；在测试里加一条断言该键存在，防止后续再次被删。

## 理由

"字段无用途"是服务端视角的结论，不代表对端可以接受缺键。保留一个 `null` 字段的成本远低于一次断线回归，而且这条断言可以长期防止同类改动。
