# 发布包必须自带运行时依赖

## 困境

v0.1 的启动链路里，接收服务从 PATH 里找 `node`，证书签发调用外部 `openssl.exe`（开发机上那份来自 Git for Windows），解码进程依赖开发机装的 VC++ 运行库。开发机上一切正常，所以七个 Spec 的验证都是绿的。

直到做发布包时逐项对照「只装了 Windows 11 + OBS 的机器」才发现：`node` 不在、`openssl` 不在、Git 不在。按当时的实现打出来的安装包，用户装完是**能装不能跑**。

## 策略

1. **先列「用户机器上有什么」清单**，再决定依赖怎么处理，不要从开发机反推。三条判据：目标用户操作系统自带？随包分发？还是要求用户自己装？只有第一种不需要动作。
2. **能被消除的依赖优先消除，而不是随包补一份**。证书签发原本调 `openssl req`，改成在进程内用 `@peculiar/x509` 构造自签 X.509（P-256、IP SAN、同钥续签语义全保留），安装包少一个二进制、少一份许可证义务，用户机器少一个失败点。
3. **必须随包的运行时放固定相对位置**，启动入口按「随包路径 → PATH」顺序探测，两条路都失败才报错，且报错要指名缺什么。
4. **验证必须在「没有这些依赖」的条件下做**。开发机装过 node/Git，在本机双击安装包永远发现不了问题；判断标准是「这台机器上有没有」。

## 理由

用户不会因为我们的原型跑得通就具备同样的环境。依赖清单不能靠印象，要靠逐项对照；能消除的依赖应消除（少一个组件就少一条失败路径和一份分发义务），消不掉的（如 FFmpeg）才随包分发并承担相应许可证义务。
