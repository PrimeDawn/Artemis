# 安装器卸载顺序：先停进程再删文件

## 困境

TC-09 要求「服务正在运行时卸载」。第一次跑的结果是：卸载器返回 0、注册表键删干净了，但安装目录里留下 7 个文件——`Artemis.exe`、`runtime\node.exe`、`app\native\artemis-decode-host.exe` 和它加载的 4 个 FFmpeg DLL。

原因：Inno Setup 的 `[UninstallRun]` 段落**在文件删除之后**才执行。写在里面的 `taskkill` 来得太晚，文件已因句柄占用删不掉。

## 策略

1. **把「停进程」放进 `[Code] CurUninstallStepChanged(usUninstall)`**。这个阶段在文件删除之前触发，是唯一能保证顺序的位置。
2. **停完要等**。`taskkill` 返回不等于句柄已释放，随后 `Sleep(1500)` 再反注册、再让卸载器删文件。
3. **注册表反注册也放在同一阶段**，因为 `regsvr32 /u` 需要 DLL 还在。
4. **不要只验「卸载返回 0」**。必须断言残留文件数为 0：`(Get-ChildItem $app -Recurse -File | Measure-Object).Count`。卸载器对删不掉的文件只记录、不回报失败。
5. **子进程用 Job Object 兜底**（`JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`）：托盘被强杀时子进程跟着走，避免留下占用文件的孤儿进程。

## 理由

「卸载成功」有两个层面：程序认为自己成功了，和磁盘真的干净了。前者由退出码体现，后者只能靠文件系统断言。这一条如果不写测试就会漏——用户机器上表现为「卸载后还占几百 MB、OBS 里残留一个打不开的设备」。
