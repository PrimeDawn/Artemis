# 项目偏好

- 产品目标与一期边界以根目录 `产品规划.md` 为准。
- 优先稳定、易连接和可持续使用；一期无账号、付费订阅、云端信令或媒体转发依赖。
- 安卓使用原生 Kotlin/Compose；电脑侧面向 Windows + OBS；共仓维护连接协议。
- 默认 720p/30 fps，最低 Android 10；首个重点验收设备为 S24/Android 16。
- 采集必须由用户主动开始，明确显示相机、麦克风、连接状态与停止入口。
- 页面资源离线随包提供；连接错误给出可理解原因和恢复入口。
- 保留高信息密度但清晰的状态反馈，前端视觉由后续设计 Spec 确定。
- 模拟器、规划指标或静态检查不能代替音视频、后台与性能真机验收。
- 长期约束写 rules；设计理由写 knowledge；一次性需求写对应 Spec。
- 本项目由 Agent 新下载或安装的 SDK、模拟器、系统镜像和相关缓存放在 E:\Dev 下的项目专用目录；当前为 E:\Dev\Artemis。已有软件和用户原有缓存只在明确授权时迁移。
- 下载或安装大型组件前，先告知安装目录、预计空间和影响，再按用户确认执行；保持本项目新增缓存和临时文件在 E 盘。

## 测试时间预算（用户明确要求，2026-10-29）

- 每轮测试的实际总耗时上限为300秒（5分钟），全量测试同样适用；准备、构建/设备启动、等待与重试计入同轮预算，不通过拆轮或连续重跑规避。
- 禁止为“长期/无限时保持连接”做等时长等待；以代码/状态机审查确认没有固定或空闲TTL、身份/意图持久化、保活和重连策略，必要时用加速时钟检查边界。产品要求保持10年连接不等于等待10年验证。
- 真实设备仅做预算内必要的发现、首次确认、再次连接、故障恢复/主动停止和短时功能验证；不再安排65分钟手机保活，也不自动安排10分钟推流等超预算测试。
- 执行前选择能在总预算内完成的必要检查并设定剩余时间；到上限停止并记录未覆盖项，不为凑“全绿”继续延长。新的模拟边界须如实标记，不能声称长期实测。
- 本用户指令优先于Skill、旧Spec/Version计划和旧测试脚本中的长稳时长；旧实际运行记录只作历史证据保留，不授权今后重跑。

## 前台使用与常亮（用户2026-10-29确认）

- 手机App仅在前台且未锁屏时使用，App窗口请求保持屏幕常亮，沿用用户亮度和系统熄屏设置。
- 切换其他App或锁屏时暂停连接、发现与重试；返回App后自动恢复原被选且仍受信的电脑，不重复配对。
- 前后台暂停与显式停止分开：主动断开或取消信任后，回前台/网络回调不能自动重新激活。
- 后续媒体沿用前台使用边界，覆盖旧后台持续采集假设；后台不自动拉起App或唤醒锁屏。构建/代码实现不等于真机生命周期验收通过。

## 测试结果表述（用户2026-10-29纠正）

- 实际执行后断言失败或核心功能不可用，应明确写失败并作为验收阻断；只有尚未执行或缺少环境的项目才写未实测，不以尚未通过弱化失败。
- 手机不能连接电脑时，必须先诊断修复并复验，不能用后续功能完成或间歇成功绕过该阻断。

## 修复与验证优先级（用户2026-10-31更新，覆盖旧5分钟硬上限）

- 优先实现实际功能和修复已发现的bug；不要添加与当前故障无关的防御性编程。
- 不再卡死每轮5分钟测试上限，也不因跨过5分钟反复申请续测。对具体操作使用合理超时，避免无意义等待。
- 根据改动影响做聚焦验证；不要每改一处代码都跑全量测试。
- 长期连接仍通过代码与状态机审查及短时真实链路验证，不恢复长时间保活测试。
